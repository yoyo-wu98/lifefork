# LifeFork / 人生岔路 — 最终需求与设计规划

> 版本：Product Spec v1.0  
> 日期：2026-04-28  
> 项目阶段：本地原型 V0.4 → 可验证 MVP  
> 副标题：与那些你尚未选择的人生交谈。

## 1. 项目定义

LifeFork 是一个面向活人的自我认知与人生分支模拟产品。

它通过低门槛输入，把用户当前的记忆、选择、恐惧、愿望、语言风格和阶段性自我状态压缩成一个可编辑、可解释、可对话的 `Self Skill`。系统再基于 `Self Skill` 构建人生时间线、人生地图、分支节点和不同时间阶段的自我实例，让用户与过去、现在、未来和未选择路径中的自己对话。

核心表达：

> LifeFork 不是命运机器。它是一套自我模拟系统，用来帮助用户看见不同时间尺度下的可能性、代价、模式和行动入口。

## 2. 第一性原理

用户真正需要解决的问题：

1. 我到底是一个怎样的人。
2. 我为什么反复做类似的选择。
3. 我现在站在哪个生命节点。
4. 如果我走另一条路，会出现什么代价和可能。
5. 我如何和不同阶段的自己对话。
6. 我如何让 AI 逐渐学会我的说话方式。
7. 我如何在不上传全部人生数据的情况下，快速获得有用反馈。

因此，产品核心不是“完整复制一个人”，而是：

> 把自我理解变成一个可以读取、缩放、编辑、分岔和继续对话的系统。

## 3. 非目标

LifeFork 明确不做以下定位：

- 不做算命。
- 不做心理诊断。
- 不做医疗建议。
- 不做 AI 伴侣恋爱陪伴。
- 不做数字永生。
- 不声称上传意识。
- 不替用户做最终决定。
- 不鼓励用户依赖系统。
- 不自动抓取微信或第三方私密数据。

## 4. 产品形态

LifeFork 的体验应同时具备三种属性：

1. 自我认知工具：帮助用户识别价值观、恐惧、欲望、冲突和重复模式。
2. 人生模拟器：以时间尺度和分支节点组织用户的人生可能性。
3. 互动叙事系统：让用户像读取存档一样进入不同阶段、不同选择中的自己。

参考方向：

- `HereAfter` 的低门槛访谈和记忆保存。
- `Eternime` 的可交互人格档案概念。
- `Detroit: Become Human` 的多节点分支存档可视化。
- Apple Photos / Maps 的语义缩放体验。
- MBTI / SBTI 的低成本自我表达和社交传播性。

## 5. 核心对象模型

### 5.1 Self Skill

`Self Skill` 是用户当前自我的结构化模型。

它不是完整人格，也不是意识副本。它是一个可编辑、可审计、可导出、可版本化的自我模型包。

核心字段：

```ts
interface SelfSkill {
  id: string;
  version: string;
  createdAt: string;
  selectedVersion: "future" | "past" | "fork";
  questions: {
    currentChoice: string;
    recurringEmotion: string;
    pastNode: string;
    hiddenSelf: string;
    futureSentence: string;
  };
  extraText?: string;
  wechatAnalysis?: WeChatAnalysis;
  identity: IdentityProfile;
  voice: VoiceProfile;
  stageVoices: StageVoice[];
  semantic: SemanticProfile;
  decision: DecisionModel;
  timeline: TimelineNode[];
  evidence: Evidence[];
  claims: Claim[];
  forks: ForkPath[];
}
```

### 5.2 Instance

`Instance` 是 `Self Skill` 在某个时间点或人生路径上的运行实例。

典型实例：

- 过去的我。
- 现在的我。
- 五年后的我。
- 90 天后的我。
- 没有离职的我。
- 选择转向后的我。
- 某个小时里的我。

实例需要具备：

- 时间尺度。
- 所在分支。
- 语气模型。
- 状态变量。
- 可能获得。
- 可能付出。
- 对话入口。

### 5.3 ForkPath

`ForkPath` 是人生地图中的节点。节点可以代表一整条人生，也可以代表十年、一年、一周、一天或一小时。

每个节点包含：

- 父节点。
- 时间尺度。
- 所属 lane。
- 时间范围。
- 标题与摘要。
- gains / costs。
- stateVector。
- children。
- futureSelfVoice。
- 可进入的对话实例。

### 5.4 LifeScale

时间尺度从大到小：

```text
全人生 -> 十年 -> 阶段 -> 一年 -> 一月 -> 一周 -> 一天 -> 一小时
```

尺度不是固定线性层级。真实人生路径可以跳层，例如：

- 全人生 -> 十年 -> 一年。
- 全人生 -> 阶段 90 天 -> 一周 -> 一天 -> 一小时。
- 全人生 -> 一年 -> 一次重要谈话。

系统显示规则应以父子包含关系为主，时间尺度为辅助。

## 6. 最终核心需求

### 6.1 低门槛进入

用户第一次使用时，只需要：

1. 选择想见哪个版本的自己。
2. 回答五个核心问题。
3. 可选粘贴文本。
4. 可选导入微信聊天记录文本。
5. 点击生成。

五个问题：

1. 你现在最纠结的一个选择是什么？
2. 你最近反复出现的情绪是什么？
3. 你人生中最想重新理解的一个节点是什么？
4. 你觉得自己最不像别人看到的哪一面？
5. 如果十年后的你回头看今天，你最希望 TA 说什么？

### 6.2 Self Skill 生成

系统应生成：

- 主线人格。
- 一句话自我叙事。
- 语言风格。
- 情绪基调。
- 核心价值观。
- 核心恐惧。
- 欲望。
- 反复模式。
- 决策模型。
- 人生母题。
- 证据引用。
- 人生时间线。
- 人生地图初始分支。
- 阶段语气模型。

关键要求：

- 重要判断必须尽量链接证据。
- 结论可被用户修改。
- AI 输出应避免绝对化命运表达。
- 本地规则 fallback 必须可用。

### 6.3 微信聊天记录导入

产品应支持用户主动导入微信聊天记录文本。

V0 输入方式：

- 粘贴文本。
- 上传 `.txt` / `.csv` / `.json` / `.html` / `.md`。

V0 处理方式：

- 浏览器本地规则分析。
- 识别说话人。
- 识别高频主题。
- 识别情绪线索。
- 提取关键片段。
- 基础脱敏邮箱、手机号、链接。
- 生成 `WeChatAnalysis`。
- 将摘要信号输入 Self Skill。

未来增强：

- 分块摘要。
- 摘要树。
- 说话人归一。
- 长文本 token 预算。
- 向量检索。
- 增量导入。
- 去重。
- 用户可选择是否保留原文。
- 完整隐私审计。

隐私原则：

- 不自动抓取微信。
- 不绕过平台限制。
- 用户主动导出、主动粘贴、主动上传。
- 默认不把微信原文写入 Self Skill。
- 启用 AI API 时，必须明确说明哪些摘要会发送到模型供应商。

### 6.4 语气学习

这是最重要的长期能力之一。

系统需要持续学习：

- 用户常用词。
- 句子长度。
- 标点习惯。
- 情绪表达方式。
- 自嘲方式。
- 犹豫方式。
- 克制程度。
- 锋利程度。
- 口语化程度。
- 不同人生阶段的表达差异。

要求：

- 过去的我、现在的我、未来的我、分支里的我，不能使用同一套语气。
- 每个阶段都应有 `StageVoice`。
- 用户可以持续校准。
- 校准反馈进入 `SelfSkill.voice.calibrationNotes`。
- 每次聊天都应逐步靠近用户表达。

语气校准按钮：

- 这句像我。
- 少一点 AI 味。
- 更口语。
- 更克制。
- 更锋利。

未来应支持：

- 用户直接改写一句回复。
- 系统从改写中学习。
- 阶段语气版本化。
- 聊天记录驱动的语气微调。

### 6.5 人生时间线

时间线负责从过去到现在整理用户的人生材料。

节点字段：

- 阶段/年份。
- 标题。
- 情绪。
- 模式。
- 语气。
- 证据。

操作：

- 标记准确。
- 修改。
- 删除。
- 后续新增节点。
- 与人生地图节点联动。

目标：

- 帮用户看到“我不是突然变成现在这样，而是在多个节点中逐步形成现在的我”。

### 6.6 人生地图

人生地图是核心体验。

设计目标：

- 像游戏存档读取。
- 像地图一样缩放。
- 像人生模拟器一样分岔。
- 像时间线一样有从出生到现在的连续性。

#### 6.6.1 基本布局

初始显示：

- 人生从左到右展开。
- 左侧是出生、早年、关键过去节点、暗线。
- 中间是现在的生活点。
- 未来分支从现在向右生长。
- 初始镜头聚焦现在，但能看见来路。

#### 6.6.2 包含关系

父节点代表较大时间段，子节点代表较小时间段或内部选择。

强规则：

- 如果小框代表的时间段属于大框，小框必须始终在大框内部。
- 不允许逻辑上属于内部的小框跑到父框外面。
- 大框之间尽量不重叠。
- 半透明父框不能形成视觉污染。
- 当前尺度外的上层框应淡出为低透明底图。
- 下层节点应在父框内部逐渐浮现。

#### 6.6.3 语义缩放

缩放效果参考 Apple Photos 和地图应用：

- 大尺度：看到全人生主线。
- 放大：宏观框逐渐变成半透明底图。
- 下一层节点在父框内部显现。
- 时间框大小随尺度明显变化。
- 放大到一定程度后自然切换到更细尺度。
- 缩小时从细节重新回到宏观框。

缩放原则：

- 相对位置稳定。
- 镜头变化时树结构不能跳。
- 过渡应丝滑、线性可理解。
- 双指缩放方向必须符合用户直觉。
- 滚轮和触控板需要可用。

#### 6.6.4 焦点模式

双击节点应在三种模式之间循环：

1. 聚焦单个节点。
2. 聚焦并包含父节点与当前节点。
3. 聚焦并包含当前节点与直接子节点。

要求：

- 在“当前节点 + 子节点”模式下，子节点必须可见。
- 如果父子距离较长，镜头必须同时容纳父子。
- 子节点不能因尺度过滤被隐藏。
- 当前焦点路线要清楚。

#### 6.6.5 拖拽

节点可拖动。

规则：

- 拖动父节点时，其所有子节点、孙节点继续保持相对位置并一起移动。
- 祖先节点的大框应自适应更新大小。
- 拖动不能破坏父子包含关系。
- 拖动后布局状态可暂存在本地。

#### 6.6.6 连线

连线规则：

- 普通兄弟/路径连接走左右边缘。
- 父框连接内部子框时，从父框内部左侧起线。
- 大虚线框的连线接口不能落在框中心。
- 连线需要弱化非焦点路径，避免混乱。

#### 6.6.7 节点类型

地图节点类型：

- life-map：人生地图节点。
- direction：方向选择。
- strategy：策略选择。
- consequence：后果节点。
- ending：阶段性结局。
- life-node：历史或当前节点。

未来可扩展：

- merge：合流节点。
- lock：锁定节点。
- memory：记忆节点。
- action：行动实验节点。
- evidence：证据节点。

### 6.7 未来自我对话

用户可进入任一人生节点，与对应阶段的自己对话。

对话要求：

- 以该节点的时间尺度和语气回答。
- 结合 gains / costs / stateVector。
- 不给确定命运判断。
- 给出可能性、代价、提醒和行动入口。
- 支持快捷问题。
- 支持语气校准。

快捷问题：

- 你后悔吗？
- 你失去了什么？
- 你会提醒现在的我什么？
- 这条路最难的地方是什么？
- 我应该从哪一步开始？

### 6.8 分享卡片

分享卡片应适合截图和社交传播。

内容：

- LifeFork / 人生岔路。
- 主线人格。
- 核心冲突。
- 当前选择。
- 当前时间点。
- 未来自我箴言。
- 项目标语。

隐私规则：

- 默认不展示微信原文。
- 默认不展示完整私人事件。
- 不展示敏感联系人信息。

操作：

- 复制结果。
- 导出 Self Skill JSON。
- 再生成一句未来自我的话。
- 回到人生地图。
- 重新开始。

## 7. 用户流程

### 7.1 新用户主流程

```text
Landing
  -> 选择想见的自己
  -> 五问访谈
  -> 微信导入，可跳过
  -> 额外文本，可跳过
  -> 生成 Self Skill
  -> 自我画像
  -> 时间线
  -> 人生地图
  -> 选择节点
  -> 未来自我对话
  -> 分享卡片 / 导出 JSON
```

### 7.2 老用户回访流程

```text
打开应用
  -> localStorage 恢复
  -> 回到上次 step
  -> 继续人生地图 / 当前对话 / 分享卡片
```

### 7.3 高价值流程

用户输入一个人生问题后，系统应帮助用户看到：

- 保持现状的路径。
- 激进转向的路径。
- 低风险试验的路径。
- 关系安放的路径。
- 每条路径内部继续分叉。
- 每个节点能进入具体对话。

## 8. 技术架构

### 8.1 当前架构

```text
Client
  Next.js App Router
  React Components
  Zustand Store
  localStorage
  Local Engines

Server Routes
  /api/generate-self-skill
  /api/chat
  /api/wechat-analyze

AI Layer
  DeepSeek client
  Prompt builders
  Local fallback
```

### 8.2 状态管理

Zustand store 是当前单一状态中心。

管理：

- step。
- selectedVersion。
- answers。
- extraText。
- wechatRaw。
- wechatAnalysis。
- selfSkill。
- selectedFork。
- previewForkId。
- messages。
- badge。
- proverb。
- isGenerating。

未来应拆为：

```text
navigationSlice
inputSlice
selfSkillSlice
mapSlice
chatSlice
storageSlice
```

### 8.3 AI 策略

当前策略：

- API 优先。
- 本地规则 fallback。
- API 错误不阻塞核心体验。

要求：

- 未配置 API key 时应明确进入 disabled mode。
- 本地 fallback 必须产出完整 Self Skill。
- AI 输出必须可被 schema 校验。
- 不合格输出必须降级。

### 8.4 数据存储

V0：

- `localStorage`。

Key：

- `lifefork.selfSkill`
- `lifefork.currentStep`
- `lifefork.selectedFork`
- `lifefork.chatMessages`
- `lifefork.wechatAnalysis`

MVP 后：

- 本地优先 IndexedDB。
- 可选云同步。
- 加密存储。
- Self Skill 版本历史。
- 数据导出/删除。

## 9. 安全与伦理

### 9.1 基本原则

- 模拟，不预言。
- 反思，不操纵。
- 辅助，不替代决策。
- 用户拥有数据。
- 用户可导出、可清空。
- 不鼓励情感依赖。
- 不做心理诊断。

### 9.2 危机处理

如果检测到：

- 自杀。
- 不想活。
- 死了算了。
- 伤害自己。
- 杀人。
- 报复。
- 毁掉。
- 活不下去。
- 割腕。
- 跳楼。

系统停止常规模拟，显示现实支持提示。

### 9.3 隐私边界

需要清楚区分：

- 本地分析。
- 服务端 API。
- 第三方模型供应商。

产品文案必须明确：

- 哪些数据只留在浏览器。
- 哪些摘要会发到服务端。
- 启用 AI API 后哪些内容会发给模型。
- 微信原文是否保留。
- 如何删除。

## 10. 商业与传播定位

### 10.1 定位句

> LifeFork 是一个自我模拟引擎，让用户把自己保存成可编辑、可解释、可对话的 Self Skill，并在不同人生尺度上读取自己的可能性。

### 10.2 传播语

- 与那些你尚未选择的人生交谈。
- 你不是一个结论，你是一条正在分岔的河流。
- MBTI 给你一个标签，LifeFork 给你一条时间线。
- 和过去的你和解，和未来的你谈判，和未选择的你重逢。
- 不预测命运，只召唤可能性。

### 10.3 目标用户

早期用户：

- 处在人生选择节点的人。
- 创作者。
- 转行者。
- 大学生/研究生。
- 想整理人生材料的人。
- 对 MBTI/SBTI/人生模拟感兴趣的人。

- 可打开人生地图。
- 可切换时间尺度。
- 可选择人生节点。
- 可进入对话。
- 可校准语气。
- 可生成分享卡片。
- 可导出 JSON。
- 可清空数据。

### 12.2 地图验收

- 大框之间不明显重叠。
- 子框始终位于父框内部。
- 当前尺度的子节点可见。
- 父子同屏能同时看到父节点和子节点。
- 拖动父节点时后代一起移动。
- 双指缩放方向正确。
- 滚轮缩放可用。
- 拖拽平移可用。
- 连线从左右边缘或父框内部左侧发出。

### 12.3 AI 与安全验收

- 无 API key 时 fallback 正常。
- API 出错时 fallback 正常。
- 危机关键词触发安全提示。
- 回复不使用确定性命运判断。
- 语气校准可以影响后续回复。

### 12.4 隐私验收

- localStorage keys 明确。
- 用户可清空本地数据。
- 微信原文默认不写入 Self Skill。
- 启用模型 API 时有清楚提示。

## 14. 最终产品判断

LifeFork 的关键竞争力不在“生成三条建议”，而在以下组合：

1. 用户可以把自己保存成 Self Skill。
2. Self Skill 可以被证据校准。
3. 人生地图支持大尺度到小尺度的语义缩放。
4. 不同时间阶段拥有不同语气。
5. 用户可以和每个节点里的自己对话。
6. 用户可以持续修正系统对自己的理解。

最终体验应让用户感觉：

> 我不是在填问卷，也不是在和普通聊天机器人说话。我是在读取一张关于自己的时间地图。
