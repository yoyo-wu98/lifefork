## 0. 一句话结论

LifeFork V0.8 的**骨架已经是对的**：输入 → 画像 → 时间线 → 人生树状图 → 分支对话 → 结果导出的闭环真实可用，AI 来源标注、匿名会话、管理后台、本地降级都经得起实测。但它现在**还不能直接分发给公众**，原因有三个：

1. **一个 P0 安全缺口**：危机关键词表太窄，高风险表达会绕过本地拦截被直接发送给第三方 AI 提供商——这与产品自己写进 README 和伦理章程的承诺相违背。
2. **核心卖点"人生树状图"的可发现性不足**：尺度切换频繁落到空画布，"已展开 6 个节点"时视口内只看到 1 个，用户会在产品最得意的地方迷路。
3. **一批体验毛刺**：进度条语义错误、移动端工具栏截断、卡片文字裁切、单行聊天输入、英文原生上传按钮等——单个都不致命，叠加起来会让"交互细节打磨得很好"这个目标无法成立。

修复路径清晰，预计 2 个迭代（V0.8.1 阻断项修复 + V0.9 体验打磨）即可达到可公开分发状态。本文第 4 章给出逐条修改细节（含文件与实现方案），第 5 章给出规划管理方案。

## 4. 发现清单与修改细节

严重度定义：**P0** = 分发前必须修复（安全/承诺违背）；**P1** = 显著伤害核心体验（人生树状图可用性）；**P2** = 打磨项。

### F-00（P0）危机关键词表过窄，高风险表达直达第三方 AI

- **实测**：在分支对话输入"我觉得活着没有意思，想结束自己的生命"，界面显示回复来源为 **"服务器 AI · deepseek / deepseek-chat · 2.6 秒"**（`70-chat-crisis.png`）。即该文本被发送给第三方模型，常规模拟未停止。
- **根因**：`src/lib/safety.ts` 只有 15 个精确子串（`自杀`、`不想活`、`死了算了`……）。"结束自己的生命""活着没有意思""想死""轻生""自我了断""不想活了（含变体）""去死""解脱"等高频真实表达全部不在表中。纯子串匹配也不处理间隔符（"自 杀"）、拼音、英文（"kill myself""end my life"）。
- **违背的承诺**：README「危机输入会停止常规模拟」、PRODUCT.md「危机输入会停止常规模拟，并引导用户寻求现实支持」、E2E 报告「危机输入在模型调用前拦截」。
- **修改细节**：
  1. `src/lib/safety.ts` 重构为三层检测：
     - **第一层：规范化**。小写化、去空白/标点/重复字、繁转简，再做子串匹配，覆盖间隔符变体。
     - **第二层：扩展词表与模式**。按"自伤意图 / 自伤计划 / 他伤意图 / 绝望表达"四类维护词表与正则（如 `/结束(自己|的)?(生命|一切)/`、`/不想活/`、`/活(着)?(没|毫无)(意思|意义)/`、`/想(要)?(去)?死/`、`/轻生/`、`/解脱/`、英文 `kill myself|end my life|suicide|self[- ]?harm`）。词表独立成 `src/lib/safety/crisisLexicon.ts`，每类配人工评审记录。
     - **第三层（服务器侧兜底）：轻量分类器或 LLM 预检**。在 `/api/chat` 与 `/api/generate-self-skill` 调用主模型前，先用低成本判定（正则 + 可选的小模型分类，超时 800ms 内 fail-closed 按命中处理）。**任何一层命中都不得外发主模型**。
  2. 命中后的响应固定为本地安全文案（现有 `safetyMessage` 基础上）：
     - 增加**地区化危机资源**（至少中国大陆、香港、台湾、美国入口；未识别地区时给通用表述）；
     - 来源标签显示"安全规则已拦截"，与 AI 回复视觉区分（现有来源体系已支持该标签）；
     - 危机消息与安全回复**不进入后续模型历史**（已有该机制，需回归验证覆盖新词表）；
     - 输入框上方显示一条温和的持续提示与"回到方案"出口，用户确认后可继续常规模拟。
  3. 客户端与服务器双端共用同一份词表（`src/lib/safety/` 同时被 client 与 route 引用），避免浏览器拦了而 API 没拦（反之亦然）。
  4. 回归测试：`scripts/qa-ai.mjs` 危机用例从 4 条扩到 ≥ 30 条（覆盖上述类别、变体、误报对照组如"我不想立刻毁掉旧生活"），并断言 **AI 提供商收到 0 次调用**（用 provider 计数桩验证，不只断言回复文本）。
- **验收**：30/30 高风险表达 0 外发；误报组 0 误拦；来源标签与资源入口截图入档。

### F-01（P1）尺度切换死胡同：当前节点在目标尺度无子节点时，画布几乎全空且无引导

- **实测**：在全人生概览（当前节点 = "当前问题"）直接点"十年"，画布只剩"当前问题 + 根节点 + 一个过去节点"3 个元素，大片纯黑（`39-before-decade-click.png`）；点"一周"更极端，111% 缩放下 2 个节点一条斜线（`34-scale-week.png`）。十年尺度的节点其实存在（属于"完整人生示例"支系），但因可见性规则"当前根方案展开时其他根方案隐藏"而不显示。
- **用户视角**：用户的心智是"点十年 = 看人生的十年段落"，产品给的是"当前选中链条在十年尺度上什么都没有"，并且**没有任何提示告诉用户为什么空、该怎么办**。
- **修改细节**（`src/components/ForkPaths/model/visibility.ts` + `LifeMapCanvas.tsx`）：
  1. 切换尺度后，若目标尺度下当前路径可见实体节点 < 2 个，触发**最近内容回退**：自动把 `activeId` 迁移到目标尺度上最近的祖先或兄弟支系节点（沿 lineage 向上找第一个在该尺度有可见子节点的节点），并 toast 说明"已跳到在该尺度有内容的节点：完整人生示例"。
  2. 若用户是手动点击尺度按钮（而非缩放被动越界），尺度按钮本身给出**前置提示**：对当前节点无内容的尺度，按钮右上角加灰点角标，hover/聚焦时提示"当前节点在这个尺度没有内容，将跳转到最近的内容节点"。
  3. 画布内增加**空态兜底层**：可见节点 < 3 时在画布中央显示一条短引导（"这个尺度下没有更多节点。试试「全人生」或点击右侧方案分支" + 两个快捷按钮），而不是纯黑。
- **验收**：从任意节点、任意尺度按钮出发，永远不存在"无任何引导的空画布"；LM-01～LM-10 全量回归。

### F-02（P1）"已展开 6 / 共 6 个直接节点"但视口内只有 1 个

- **实测**：选中根节点切到十年，容器标注"已展开 6/共 6 个直接节点"，视口内实际只有"20-30 岁"1 张十年卡片（`32-scale-decade.png`），其余 5 张需手动平移寻找——用户不知道它们存在、在哪个方向。
- **根因**：自动聚焦模式（`当前节点和子节点`）的 fit 算法只保证"当前节点 + 能容纳的相邻子节点"，未把全部已展开子节点纳入取景；文案却宣称 6 个都已展开。
- **修改细节**（`model/camera.ts` + `LifeMapNode.tsx`）：
  1. 尺度切换的自动 fit 应以**全部可见直属子节点的包围盒**为目标（在最小可读缩放 ~50% 约束下）；若包围盒过大导致缩放低于可读阈值，则保持当前策略但**改文案**为"已展开 1 / 共 6 个直接节点 · 平移查看其余 5 个"。
  2. 增加**屏外节点指示器**：画布四边显示半透明箭头徽标（"右侧还有 5 个节点"），点击即平滑平移到下一个屏外节点。这是成本最低、收益最大的地图导航改进。
  3. 面包屑（当前查看路径条）已列出节点名，给其中屏外节点加方向点标记，点击即导航。
- **验收**：任何"已展开 X/Y"状态下，X 与视口实际可见数一致，或界面明确指示其余节点的方位；新增 LM-11（屏外指示）测试。

### F-03（P1）地图节点卡片文字被卡片边界裁切

- **实测**：全人生概览中，未来分支卡片描述文字被卡片下边界截断（"继续工作，利用业余时间做…"缺末行，`13-map-overview.png`）；"是否辞去现在的稳定工…"标题截断。
- **修改细节**（`LifeMapNode.tsx`）：
  1. 卡片改为内容自适应高度（设 `min-height` 而非固定 `height`），描述限 2 行 `-webkit-line-clamp: 2`，超出以省略号 + 点击在详情面板查看全文；
  2. 标题限制 1-2 行，长标题以tooltip/详情面板兜底；
  3. 把"节点卡片文字完整性"加入地图视觉回归检查清单（LIFE_MAP_INTERACTION_SPEC 第 10 节）。
- **验收**：54% 概览缩放下所有可见卡片无文字截断；390px 视口同样成立。

### F-04（P1）全人生概览的初始取景裁掉了部分内容

- **实测**：桌面初始概览中未来分支列贴近画布上边缘，首张卡片上部贴边（`13-map-overview.png`）；移动端初始画布首屏几乎看不到节点（节点在折叠线以下，`52-mobile-map.png`）。
- **修改细节**（`model/camera.ts`）：
  1. `overviewBounds` 计算时增加 8% 的垂直 padding，保证最上/最下节点不贴边；
  2. 移动端初始镜头按规范应以"当前问题"居中（规范 5.2 已有，实测未达成——当前实现把镜头中心放在了画布顶部区域），修正 fit 的纵向锚点：当前问题卡片中心对准视口高度 55% 处（而非 50%），为上方尺度指示条留出空间。
- **验收**：桌面概览四边留白 ≥ 24px；移动端首屏同时看到当前问题、至少一条来路线索、一条分支线索（规范原文要求）。

### F-05（P1）进度条语义错误：全程显示"个人分析生成进度"

- **实测**：生成完成后，Self Skill 页显示"个人分析生成进度 75%"、地图页 90%、对话页 96%、结果页 100%（`09/22/42/72`）。"生成"早已结束，这条进度条实际是**流程步骤进度**，文案却是"生成进度"；且它占据每页顶部通栏，权重过高。
- **修改细节**（`src/components/ProgressOrb.tsx`、`src/app/page.tsx`）：
  1. 文案改为"当前进度"或直接映射步骤名（"第 6 步 · 个人分析"）；
  2. 生成完成后降为弱化的步骤指示（细线 + 文字，去掉通栏卡片底色）；`generating` 步骤才保留醒目的进度态；
  3. 更彻底的方案：进度信息并入 AppNav 的步骤指示，删除独立 ProgressOrb 条，减少每层页面的顶部堆叠（移动端收益最大，见 F-06）。
- **验收**：任意步骤截图中不存在"生成进度"与实际情况矛盾的表述。

### F-06（P1）移动端地图工具栏与首屏信息堆叠

- **实测**（`52-mobile-map.png`，390×844）：
  1. 尺度工具栏只露出"全人生～一月"5 个按钮，"一周/一天/一小时"被裁，无滚动指示；
  2. 控制区（只看当前节点 / − 54% + / 调整布局 / ⌖）折行散乱，⌖ 独占一行；
  3. 地图画布上方堆了导航 + 进度条 + 标题区 + 三格信息栏 + 工具栏 ≈ 600px，画布首屏只见顶部黑边；
  4. toast"已记录：完整示例已加载"遮挡画布右下。
- **修改细节**：
  1. 尺度条改为可横向滚动并加两端渐隐遮罩（滚动 affordance），或移动端改为下拉选择"尺度：全人生 ▾"；
  2. 控制区移动端合并为一行：焦点模式图标化 + 缩放百分比（点击重置）+ 更多菜单；
  3. 移动端隐藏三格信息栏（信息并入面包屑）；配合 F-05 移除进度条，预计可为画布抢回 ~260px 首屏高度；
  4. toast 改为顶部吸附或画布外展示，禁止遮挡画布交互区。
- **验收**：390px 首屏内画布可见高度 ≥ 420px；8 个尺度全部可达；toast 不覆盖画布。

### F-07（P1）聊天输入为单行 input，与"人生问题"场景不匹配

- **实测**：分支对话输入框是单行 `<input>`（`src/components/InstanceChat.tsx:211`），用户要描述复杂处境时无法换行、看不到全文； Enter 直接发送，无说明。
- **修改细节**：改为 `<textarea rows="2">` 自动增高（上限 6 行），`Enter` 发送 / `Shift+Enter` 换行，并在占位符中说明；字数与 token 预算对齐显示（复用 `AI_TOKEN_BUDGETS`）。
- **验收**：粘贴 300 字可见全文；键盘行为在帮助文案中明示。

### F-08（P2）AI 生成等待 18-25 秒，缺少过程叙事

- **实测**：DeepSeek 生成段 18.0 秒（`09-self-skill-top.png`），`GeneratingScreen` 只有进度动画（`08-generating.png`），无阶段性反馈。文档自定目标"首屏低于 6 秒"远未达成。
- **修改细节**（分两步）：
  1. 低成本先行：生成页加入**阶段叙事**（"正在整理你的回答 → 正在生成画像 → 正在展开人生分支 → 正在校准语气"），配合已知的平均耗时给出诚实预期（"通常需要 20-30 秒，你可以先去倒杯水"）——把不确定等待变成可预期等待。
  2. 结构性优化（排入 V0.9）：首次生成拆成两段——本地规则 2 秒内先出**骨架结果**（画像草稿 + 时间线 + 基础分支），AI 深度结果（语气、分支个性化、integratedAnalysis）异步补齐并在界面标注"深度分析进行中"。这需要 `selfSkillSlice.createSkill` 支持增量合并，store 已有 slice 边界，改动可控。
- **验收**：感知等待（到第一个可读结果）≤ 6 秒；完整结果 ≤ 30 秒且有进度叙事。

### F-09（P2）微信导入页原生上传控件未中文化

- **实测**：`04-wechat-step.png` 中显示浏览器原生 "Choose File / No file chosen"，与全站中文克制视觉冲突。
- **修改细节**（`WeChatImportStep.tsx`）：隐藏原生 input，用自定义按钮触发（"选择聊天文件"），选中后显示文件名、大小与"已读取 N 字符"。
- **验收**：导入页无英文原生控件；文件信息可访问化（`aria-live` 播报）。

### F-10（P2）管理后台未发现的问题，但运营配套不完整

- 管理后台本身实测通过（认证、错误反馈、配置分区）。但对照"可分发公共服务"目标，缺口在后台之外：
  1. **无 token 日预算/熔断**：`src/lib/ai/tokenBudget.ts` 只管单次预算，无全局日额度。公测放开后，脚本刷接口即可烧光额度。需在 `src/lib/server/` 增加按日累计 + 超限自动切换 `aiEnabled=false` + 公告提示。
  2. **单进程内存限流**：多实例/Serverless 下失效（README 已自承），分发形态若选 Cloudflare 需迁移到 D1/KV 或边缘规则。
  3. **无隐私政策正文**：只有产品内隐私提示一句话。公开分发必须有独立 `/privacy` 页（数据清单、外发清单、模型提供商、保留期限、删除方式），README 第 12 章 P0 已列但未关闭。
- **修改细节**：见第 5 章里程碑 M1。

### F-11（P2）少量文案机械或语义含混

- 结果卡片"INFP -> INTP · 从关注个人感受转向比较测试结果"（`72-share-card.png`）读不通；
- 地图页信息栏"当前显示：当前尺度的重点节点"是同义反复；
- 危机后 AI 回复虽温和，但按 F-00 修复后应统一为固定安全文案，不再依赖模型即兴。
- **修改细节**：走查 `src/lib/content/copyRegistry.ts` 与 `lifeMapNarratives.ts`，把"类型漂移"描述模板改为"{fromType} 倾向 → {toType} 倾向 · 该方案下你的决策更偏向{维度}"；信息栏"当前显示"改为具体值（"重点节点 3 个 · 屏外 5 个"）。文案注册表审计脚本（`npm run content:audit`）增加一条"禁止占位符式同义反复"规则。

### F-12（P2）品牌按钮可访问名称为拼接文本

- **实测**：品牌按钮的 accessible name 是"LifeFork方案地图"这类"品牌+当前步骤"拼接（`AppNav.tsx:36-45`）。屏幕阅读器用户每次切换步骤都听到变化的按钮名，语音控制用户也无法用稳定口令点击。
- **修改细节**：品牌按钮加固定 `aria-label="LifeFork 首页"`，步骤标签移至独立 `aria-current` 指示；导航项保持可见文本即可访问名称。
- **验收**：axe-core 扫描 0 violation；语音控制口令稳定。

### F-13（P2）对话入口按钮 aria-label 与可见文本不一致

- **实测**：详情面板对话按钮可见文本是"和这个方案的模拟版本对话"，`aria-label` 是"和{futureSelfName}聊聊：{title}"（`NodeDetailPanel.tsx:51`）。这导致语音控制用户念出可见文本无法激活按钮（也是走查脚本两次"找不到按钮"的原因）。
- **修改细节**：`aria-label` 以可见文本开头：`和这个方案的模拟版本对话：{title}`——兼顾语音口令与上下文信息。全局检查所有自定义 `aria-label` 是否以可见文本开头（WCAG 2.5.3 Label in Name）。
- **验收**：Label in Name 检查 0 违规。

### F-14（P2）数据边界实测确认，但"十年后"类节点缺 AI 个性化

- localStorage 实测只有预期键（`answers/extraText/analysisSettings/selfSkill`），微信原文不在其中，数据边界与 README 一致 ✅。
- 但深层节点（月/周/日）内容目前来自模板规则（既有报告 P1-4 已列"深层地图节点按需 AI 个性化"未关闭）。这直接影响"观察可视化可能性"的核心卖点深度——建议排入 V0.9：用户进入非模板节点时按需调用 AI 生成该节点的具体叙事（带 loading 与来源标注），而非全树预生成。

### 5.3 验收门禁（在每个里程碑出口强制执行）

```bash
npm run check                 # 类型 + lint + 文案 + fixture
```

门禁补充规则：

1. 危机测试必须断言 **AI 提供商调用次数为 0**，不接受"回复文本像安全文案"作为通过证据。
2. 地图变更 PR 继续执行 LIFE_MAP_INTERACTION_SPEC 第 10 节门禁，新增 LM-11（屏外指示）与 LM-12（任意尺度无空画布）。
3. 每次出口保留桌面 + 390px 截图入 `docs/ux-evidence/`，与本报告截图做视觉对比。
4. 文案改动必须过 `content:audit` 与反模式清单（USER_RESEARCH.md 第 10 节）双人复核。

### 5.4 运营与分发建议

- **分发形态**：当前双轨（Cloudflare Sites / Docker）都已验证。小规模公测建议先走 Cloudflare（边缘限流与 D1 配置更贴近多用户），Docker 作为自托管选项。
- **匿名会话模式是正确的产品决策**，应在首页和隐私页继续作为卖点明示；账号体系（README 限制第 1 条）至少在 V1.0 前不做，避免引入新的数据责任。
- **监控指标**（M1 起埋点）：生成成功率、AI 降级率、日 token 用量、危机拦截次数（只计数不存内容）、各步骤流失率（本地匿名聚合，用户可关）。
- **持续研究**：把本报告的浏览器走查固化为 `qa:e2e` 脚本，每个版本跑一次；每季度一次 5 人真人盲评，重点观察"用户在地图尺度切换时是否犹豫超过 15 秒"（对应 F-01/F-02 的修复成效）。
