# LifeFork User Research & Product Requirement Briefs

> Owner: Product & Research Team
> Last updated: 2026-04-29
> Scope: 用户问题、核心体验、版本价值、竞品对照、可用性测试脚本、验收标准。

## 1. Research Position

LifeFork 的研究目标不是证明用户需要一个“预测未来”的工具，而是验证用户是否愿意把自己的材料整理成一个可编辑、可解释、可对话的自我模型。

核心研究问题：

1. 用户能否在 5 个问题内理解 LifeFork 的输入方式。
2. 用户是否认为 `Self Skill` 比普通聊天建议更有个人相关性。
3. 用户是否能理解人生地图的时间尺度和分支节点。
4. 用户是否愿意进入某个节点，与那个版本的自己对话。
5. 用户是否能识别 LifeFork 的边界：可能性模拟，不是命运预测、心理治疗或最终决定。

## 2. Primary User Segments

| Segment | Current pressure | Desired value | Risk to avoid |
| --- | --- | --- | --- |
| 人生选择节点用户 | 转行、离职、关系、城市、学业选择 | 看清代价、模式和可逆行动 | 被产品暗示“正确命运” |
| 创作者 | 表达停滞、自我怀疑、身份转换 | 整理长期主题和表达语气 | 把用户包装成标签 |
| 大学生/研究生 | 方向焦虑、身份探索、关系压力 | 用低成本方式形成自我叙事 | 过度心理诊断化 |
| 高反思用户 | 有日记、聊天记录、备忘录 | 把散落材料变成结构化自我模型 | 泄露私密材料 |
| MBTI/SBTI 兴趣用户 | 喜欢低门槛自我表达 | 获得比标签更动态的时间地图 | 变成娱乐化性格测试 |

## 3. Version Product Requirement Briefs

### PRB V0.5: Stable Local Prototype

用户价值：

- 用户可以在无账号、无后端、无 API key 的情况下完整体验 LifeFork。
- 用户能生成、查看、校准、导出和清空自己的 `Self Skill`。
- 用户明确知道数据保存在本地，产品不提供命运预测或治疗建议。

Must have:

- 五问 onboarding 到分享卡片完整闭环。
- 人生地图尺度切换、节点选择、进入对话可用。
- 微信聊天文本只做本地规则分析，默认不保存完整原文到 `Self Skill`。
- 危机表达触发安全提示，停止常规模拟。
- README 与需求文档明确当前限制和伦理边界。

Acceptance:

- 3 名内部试用者可独立完成完整流程。
- 试用者能说出 `Self Skill` 是“可编辑自我模型”，不是人格复制。
- 试用者能找到清空本地数据入口。
- 对话回复没有“你一定会”“命中注定”“我唯一懂你”等表达。

### PRB MVP: Evidence-Linked Self Simulation

用户价值：

- 用户能看到系统为什么这样理解自己，并能修正不准确判断。
- 用户能把人生地图当作探索工具，而不是只能观看的生成结果。

Must have:

- `Self Skill` 版本化和 schema migration。
- claims 与 evidence 的稳定关联。
- 人生地图拖拽持久化和基础编辑。
- AI disabled mode 与 AI enabled mode 的边界提示。
- 基础 E2E 覆盖新用户路径、返回用户路径、清空路径。

Acceptance:

- 用户能编辑至少 3 类内容：时间线、语气、人生节点。
- 70% 试用者能理解“证据引用”的含义。
- AI API 出错时体验仍可完成。
- QA 能复现所有 P0 用户路径。

### PRB Phase 2: Real AI With Privacy Boundaries

用户价值：

- 用户可以导入更长文本，得到更贴近自己的结构化总结。
- 用户可以通过改写和反馈让 LifeFork 逐步接近自己的表达方式。

Must have:

- 长文本分块摘要树。
- RAG evidence retrieval。
- 用户改写学习进入 voice profile。
- 外发数据最小化和可见提示。
- 可删除、可导出、可审计的数据控制。

Acceptance:

- 用户能看到“本地保存内容”和“发送给模型内容”的差异。
- 长文本摘要保留证据索引，不暴露完整原文到不必要字段。
- 语气校准后下一轮回复可观察变化。
- 安全文案通过 Product & Research 与 QA 复核。

### PRB Phase 3: Productized Release

用户价值：

- 用户可以跨设备保存自己的模型，同时保留明确的数据控制权。
- LifeFork 可以面向小范围真实用户发布，并持续收集反馈。

Must have:

- SaaS 与本地版边界清楚。
- 账号、加密存储、删除机制。
- 分享卡片图片导出。
- 公开项目页和发布说明。
- 用户反馈收集机制。

Acceptance:

- 20 名真实用户完成 onboarding。
- 70% 用户能解释人生地图结构。
- 50% 用户进入分支自我对话。
- 所有隐私与伦理声明在发布页、产品内、README 中一致。

## 4. User Journey Map

| Stage | User question | Product response | Success signal | Research probe |
| --- | --- | --- | --- | --- |
| Arrival | 这是什么？会不会很玄？ | 明确“自我模拟，不预测命运” | 用户愿意开始 | “你觉得它像什么产品？” |
| Version choice | 我想见哪个自己？ | 未来、过去、另一条路 | 用户能快速选择 | “这个选择是否让你更想继续？” |
| Five questions | 我该写多长？ | 低门槛问题和灵感标签 | 用户完成五问 | “有没有问题让你卡住？” |
| Optional material | 我要不要放聊天/日记？ | 本地优先和隐私提示 | 用户理解可跳过 | “你担心哪些数据？” |
| Self Skill | 它真的像我吗？ | 画像、价值、恐惧、证据 | 用户指出准确/不准 | “哪一条最像你？哪一条不准？” |
| Timeline | 我为什么变成现在这样？ | 可编辑节点和准确性标记 | 用户能修正节点 | “你想补哪段经历？” |
| Life map | 我有哪些路？ | 多尺度分支地图 | 用户能进入节点 | “你理解这个节点代表什么吗？” |
| Dialogue | 这个版本会怎么回应我？ | 克制、证据化、非决定性回复 | 用户继续追问 | “回复像你吗？哪里不像？” |
| Calibration | 我能不能调语气？ | 口语、克制、锋利等反馈 | 下一轮可见变化 | “你还想提供什么校准方式？” |
| Share/export/delete | 我能控制数据吗？ | 导出 JSON、清空本地数据 | 用户找到控制入口 | “你是否相信它没有偷偷保存？” |

## 5. Competitor & Substitute Comparison

| Product / pattern | User value | LifeFork difference | Product risk |
| --- | --- | --- | --- |
| MBTI / SBTI | 低门槛身份表达、社交传播 | LifeFork 给时间线、证据和分支，不只给标签 | 过度标签化 |
| 普通 AI Chat | 即时建议、低摩擦对话 | LifeFork 以 `Self Skill`、证据和人生地图作为上下文 | 退化成建议机器人 |
| 日记 App | 记录材料、长期沉淀 | LifeFork 把材料组织成可对话模型 | 侵犯私密感 |
| 心理咨询 | 高质量现实支持 | LifeFork 不做治疗，只做自我整理和模拟 | 被误认为治疗替代品 |
| 算命/星盘 | 强叙事、低认知成本 | LifeFork 强调可编辑、可反驳、非确定 | 过度命运化 |
| 数字永生产品 | 保存记忆和人格印象 | LifeFork 面向活人当下决策，不声称复刻意识 | 过度人格复制暗示 |

## 6. Usability Test Scripts

### Script A: First-Time Complete Flow

目标：验证新用户能否独立完成完整路径。

任务：

1. 从首页开始，不看说明文档，完成五个问题。
2. 跳过或添加一段可选文本。
3. 生成 `Self Skill`。
4. 找到一条你认为准确的判断和一条不准确的判断。
5. 打开人生地图，切换一次尺度。
6. 进入一个节点对话，发送一个问题。
7. 使用一次语气校准。
8. 找到导出和清空入口。

观察点：

- 用户在哪一步犹豫超过 15 秒。
- 用户是否理解“证据”和“生成判断”的区别。
- 用户是否把节点误解成确定未来。
- 用户是否能找到数据控制入口。

通过标准：

- 8 个任务至少完成 7 个。
- 不需要研究员解释产品伦理边界。
- 用户能指出至少一个想编辑的地方。

### Script B: Privacy Boundary Comprehension

目标：验证隐私文案是否足够清楚。

任务：

1. 找到聊天记录导入入口。
2. 说明当前版本会不会上传聊天记录。
3. 说明完整原文会不会默认进入 `Self Skill`。
4. 找到清空本地数据入口。

访谈问题：

- 你愿意粘贴哪类文本？不愿意粘贴哪类文本？
- 哪一句文案让你更放心？
- 哪一句文案让你觉得产品在回避问题？

通过标准：

- 用户能正确说出 V0 是本地分析。
- 用户能说出“未来如果接入模型，需要明确提示外发内容”。
- 用户能找到删除入口。

### Script C: Voice Calibration

目标：验证“像我”是否可被感知。

任务：

1. 进入任意节点对话。
2. 发送一个真实问题。
3. 点击“更口语”或“更克制”。
4. 再发送一个追问。
5. 比较前后两轮语气。

通过标准：

- 用户能描述变化，而不是只看到按钮状态变化。
- 用户不会误以为系统已经完整复制人格。
- 用户愿意提供一句改写样例。

## 7. Product Copy Boundaries for AI Team

Allowed:

- “可能会”
- “在这条路径上”
- “可以把它当作一个假设”
- “这不是结论，更像一个可编辑草稿”
- “如果把尺度放小，下一步可以是”

Disallowed:

- “你一定会”
- “命中注定”
- “我比任何人都懂你”
- “只有我能陪你”
- “这是你的真实人格”
- “你应该马上分手/辞职/搬家”
- “这是诊断结果”

Required response shape for sensitive decisions:

1. 先承认这是选择压力，不下结论。
2. 明确这是模拟，不是最终答案。
3. 展示 2 到 3 个可能尺度或路径。
4. 给一个可逆的小行动。
5. 必要时建议用户找现实中的可信任对象或专业支持。

## 8. UI Interaction Priority for UI Team

P0:

- 数据控制入口必须可见：导出、清空、隐私提示。
- 人生地图必须优先可理解：父子关系、尺度、当前节点、进入对话。
- 证据引用必须能让用户知道“为什么系统这样说”。
- 危机/安全提示不能被视觉装饰弱化。

P1:

- 编辑入口：时间线、语气、节点摘要。
- 地图节点状态变量解释。
- 返回用户恢复进度的提示。

P2:

- 分享卡片图片导出。
- 更细的动效和仪式感。
- 高级筛选和搜索。

## 9. QA Usability Tasks

QA 每个版本至少覆盖：

- 新用户完整生成。
- 返回用户恢复。
- 微信导入跳过和导入两条路径。
- 无 API key fallback。
- AI API error fallback。
- 危机关键词触发。
- 清空本地数据。
- 语气校准后继续对话。
- 地图尺度切换和节点进入。

## 10. Anti-Pattern Checklist

每个 PR、文案、prompt、发布页都应检查：

- 过度命运化：是否暗示系统知道用户未来。
- 过度治疗化：是否使用诊断、疗效、治愈承诺。
- 过度陪伴化：是否制造“只有 AI 懂你”的依赖。
- 过度人格复制：是否声称复刻意识或保存灵魂。
- 过度权威化：是否替用户做最终决定。
- 过度娱乐化：是否把重大人生问题包装成轻浮测试。
- 过度数据索取：是否在价值未明确前索取私密材料。
- 证据缺失：关键判断是否没有来源但语气很确定。
