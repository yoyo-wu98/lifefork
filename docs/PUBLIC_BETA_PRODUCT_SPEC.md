# LifeFork V0.8 公开测试产品需求与交互规范

> 文档状态：当前实施基线
> 版本：Product Spec v0.8
> 更新日期：2026-07-31
> 适用团队：产品、研究、设计、前端、AI、数据、安全、QA、运营
> 对应发布：Public Beta

## 1. 产品摘要

LifeFork 帮助用户整理当前问题，比较几条人生方案，并理解每条方案的依据、成本和不确定性。

用户通过五个问题、可选补充材料和可选微信记录摘要建立 `Self Skill`。系统随后提供：

1. 当前个人分析。
2. 可编辑人生时间线。
3. 多时间尺度的人生方案地图。
4. 每条方案的收益、成本、状态变化和来源说明。
5. 与过去、现在、未来或分支版本的模拟对话。
6. 可复制、可导出、可删除的结果。

公开测试版允许多人同时访问。每位访客使用匿名会话，个人分析保存在自己的浏览器。服务器负责 AI 调用、限流、文化排盘和全局运营配置。

## 2. 第一性原理

用户的核心任务可以归纳为四个问题：

| 用户问题 | 产品能力 | 用户可验证结果 |
| --- | --- | --- |
| 我现在真正要解决什么？ | 五问访谈、材料提取、核心冲突 | 一份可以修正的当前分析 |
| 我为什么反复遇到类似问题？ | 证据链接、行为模式、阶段时间线 | 能指出具体材料的模式判断 |
| 我有哪些可行方案？ | 多分支生成、第三条路、行动试验 | 至少三条可比较方案 |
| 每条方案依据什么？ | 方法权重、参考度、假设、未知因素 | 每个结论和节点都有来源说明 |

产品价值来自可解释的方案比较。任何生成内容都应支持用户核对、修改或拒绝。

## 3. 产品定位

### 3.1 目标用户

主要用户：

- 正在考虑职业变动、创业、读博、迁徙或创作项目的成年人。
- 正在处理关系、家庭责任和个人发展冲突的成年人。
- 希望整理长期经历、表达方式和选择模式的用户。
- 对 MBTI、八字、紫微斗数、生肖或星座感兴趣，同时希望看到清楚来源边界的用户。

次要用户：

- 希望持续记录人生节点的长期用户。
- 进行个人反思辅助的咨询、教练或研究场景。
- 内部运营、编辑、安全和 QA 人员。

### 3.2 核心使用场景

1. **当前决策**
   用户需要比较留在现状、直接改变、低风险试验和先处理现实条件。

2. **过去复盘**
   用户希望理解某段经历如何影响现在的风险判断、关系边界或行动方式。

3. **未来方案**
   用户希望查看不同时间尺度下的收益、成本、状态变化和后续节点。

4. **阶段性格变化**
   用户希望了解不同人生阶段的 MBTI 倾向和变化原因。

5. **文化探索**
   用户主动选择八字或紫微斗数，并清楚知道该结果属于传统文化解释。

6. **表达方式校准**
   用户希望模拟版本逐渐接近自己的词汇、句长、语气和阶段差异。

## 4. 产品目标

### 4.1 Public Beta 目标

- 新用户 10 分钟内完成一次完整分析。
- 用户能在 60 秒内找到最重要结论及其依据。
- 每条主要判断显示方法来源和参考度。
- 每个人生分支显示方法贡献、假设和未知因素。
- 服务器 AI 失败后，用户仍能完成主流程。
- 公开服务支持并发访客，不向浏览器暴露 API 密钥。
- 管理员可关闭高风险功能并进入维护模式。

### 4.2 非目标

- 提供确定的未来事件预测。
- 提供心理诊断、医疗、法律或财务结论。
- 自动读取微信数据库或绕过第三方平台保护。
- 构建恋爱陪伴或长期情感依赖机制。
- 声称已上传意识或完整复刻人格。
- 使用 MBTI、八字、紫微斗数、生肖或星座进行招聘、筛选或重大决定。
- 在 Public Beta 阶段提供跨设备账号同步。

## 5. 信息架构

### 5.1 前台状态机

```text
landing
  -> questions
  -> wechat-import (可选)
  -> extra-text (可选)
  -> methods
  -> generating
  -> self-skill
  -> timeline
  -> forks
  -> chat
  -> share
```

可恢复步骤：

- `self-skill`
- `timeline`
- `forks`
- `chat`
- `share`

依赖缺失时，页面必须给出返回入口，不能停留在空白视图。

### 5.2 后台结构

```text
/admin
  -> 管理员认证
  -> 服务状态
  -> 功能开关
  -> 前台信息
  -> 保存全局配置
```

后台不出现在公开导航中。

## 6. 新用户完整流程

### 6.1 首页

首页必须回答：

1. 产品会生成什么。
2. 完成一次体验需要多久。
3. 是否需要账号。
4. 数据保存在何处。
5. 服务器 AI 如何处理内容。

主操作：`开始分析`
辅助操作：`查看完整示例`

验收：

- 首屏出现明确产品用途。
- 文案不使用命运、召唤、灵魂、永生等模糊表达作为核心说明。
- 公开测试、匿名会话、服务器密钥和浏览器保存状态可见。

### 6.2 五问访谈

固定问题：

1. 你现在最纠结的一个选择是什么？
2. 你最近反复出现的情绪是什么？
3. 哪段经历最影响你现在的选择？
4. 别人通常看不到你的哪一面？
5. 十年后，你希望这个选择带来什么具体结果？

要求：

- 每次只显示一个问题。
- 每题提供直接示例。
- 用户可以返回修改。
- 五题全部完成后才进入下一步。
- 输入长度受到前端和服务端双重限制。

### 6.3 微信记录导入

支持：

- 粘贴文本。
- `.txt`、`.csv`、`.json`、`.html`、`.htm`、`.md` 文件。

处理边界：

- 文件上限 5 MB。
- 浏览器最多保留 600,000 个字符。
- 最多分析 8,000 行。
- 关键词和情绪统计最多扫描 120,000 个字符。
- 原始微信文本不写入 `Self Skill`。
- 邮箱、手机号和链接进行基础脱敏。
- 服务器只接收 `suggestedSelfSkillText` 等短摘要。

输出：

- 高频主题。
- 情绪线索。
- 参与者数量。
- 日期范围。
- 最多六个脱敏关键片段。
- 可加入个人分析的摘要。

### 6.4 补充材料

允许用户粘贴日记、备忘录、朋友圈草稿或聊天片段。

要求：

- 明确说明该步骤可以跳过。
- 显示输入用途。
- 提醒用户避免提交没有处理权限的第三方隐私。

### 6.5 分析方法与权重

预设：

| 预设 | 目标 | 文化方法 |
| --- | --- | --- |
| 证据优先 | 现实重大选择 | 默认关闭 |
| 综合分析 | 多方法并行比较 | 默认开启 |
| 文化探索 | 增加传统文化视角 | 默认开启，权重仍低于现实方法总和 |

方法：

- 用户事实与原文。
- 行为与决策模式。
- 群体统计参考。
- AI 综合分析。
- 阶段性 MBTI 倾向。
- 八字文化解读。
- 紫微斗数文化解读。

用户可以：

- 开启或关闭方法。
- 调整每项原始权重。
- 查看归一化权重。
- 选择公历或农历。
- 提供出生日期、时间、时区、地点和排盘性别规则。
- 同意或拒绝出生信息处理。

约束：

- 八字和紫微斗数缺少必要字段时，生成按钮禁用。
- 紫微斗数当前排盘库需要男或女字段，界面必须解释用途。
- 出生信息不转发给 AI 提供商。
- 管理后台可全局关闭文化方法。

### 6.6 个人分析报告

报告顺序：

1. 当前主要特征。
2. 材料完整度。
3. 核心冲突、决策方式、表达风格和当前选择。
4. 主要判断与来源。
5. 方法状态与权重。
6. 各人生阶段的 MBTI 倾向。
7. 表达方式与阶段语气。
8. 用户材料。
9. 使用限制。

每条主要判断必须包含：

- 判断文本。
- 参考度。
- 方法贡献。
- 用户设置权重。
- 方法自身参考度。
- 对应证据。
- 方法限制。
- 用户可修正标记。

### 6.7 时间线

基础节点：

- 过去重要经历。
- 隐藏特征。
- 当前情绪和问题。
- 当前人生岔路。
- 未来期望。

操作：

- 标记准确。
- 编辑标题、情绪和模式。
- 删除节点。
- 返回个人分析。
- 进入方案地图。

### 6.8 人生方案地图

时间尺度：

```text
全人生 -> 十年 -> 阶段 -> 一年 -> 一月 -> 一周 -> 一天 -> 一小时
```

空间规则：

1. 过去在左，当前点居中，未来向右展开。
2. 每个 `ForkPath` 只有一个视觉实体。
3. 当前尺度节点显示为可读卡片。
4. 祖先节点逐步形变为低透明虚线容器。
5. 子节点始终处于父节点时间容器内。
6. 同级可见容器不能重叠。
7. 连线从父节点右侧连接到子节点左侧。
8. 父容器到内部子节点的线从父容器左侧内部起步。
9. 聚焦关系高亮后，其余连线降低到低透明度。
10. 点击只改变当前节点。
11. 双击循环三种焦点模式：单节点、父节点与当前节点、当前节点与直接子节点。
12. 放大缩小保持节点拓扑和相对位置稳定。
13. 调整布局时，节点及全部后代共同移动，祖先容器自动重新包围。

分支类型：

- 维持现状。
- 立即转向。
- 90 天低风险试验。
- 先处理关系和现实条件。

每个分支详情包含：

- 摘要。
- 预期收益。
- 需要承担的成本。
- 状态向量。
- 阶段性 MBTI 变化。
- 方法来源。
- 目标匹配参考分。
- 当前假设。
- 仍然未知。
- 进入模拟对话。

### 6.9 分支自我对话

对话输入：

- 当前 `Self Skill` 摘要。
- 当前分支摘要。
- 收益和成本。
- 时间尺度。
- 用户语言画像。
- 对应阶段语气。
- 用户校准记录。
- 有界对话历史。

快捷问题：

- 你后悔吗？
- 你失去了什么？
- 你会提醒现在的我什么？
- 这条路最难的地方是什么？
- 我应该从哪一步开始？

要求：

- 显示情景模拟提示。
- AI 请求失败后使用本地回复模板。
- 危机关键词触发安全响应。
- 用户可反馈“像我、少一点 AI 味、更口语、更克制、更直接”。

### 6.10 结果卡片与导出

结果卡片包含：

- 分支名称。
- 当前特征。
- 时间尺度。
- 阶段性格倾向。
- 核心冲突。
- 当前选择。
- 一条行动建议。

隐私：

- 分享卡不展示出生日期、微信原文、补充材料原文或第三方姓名。
- 完整 JSON 导出包含用户选择保留的全部 `Self Skill` 字段。
- 导出前应提醒用户妥善保管。

## 7. 分析来源与报告语义

### 7.1 术语

- **用户权重**：用户希望本次分析对某方法分配多少注意力。
- **方法参考度**：系统对该方法在本次输入条件下的可用程度估计。
- **综合贡献**：归一化权重乘以方法参考度，用于排序和说明。
- **材料完整度**：输入材料覆盖程度。
- **分支参考分**：方案与当前目标、顾虑和材料的匹配程度。

以上字段都不能解释为未来发生概率。

### 7.2 来源标签

| 标签 | 含义 |
| --- | --- |
| 用户材料 | 直接来自用户回答、文本或确认节点 |
| 统计参考 | 群体层面研究和公开基准 |
| 模型整理 | 本地规则或服务器 AI 的综合 |
| 阶段性格 | 特定阶段下的 MBTI 偏好估计 |
| 文化解读 | 八字、紫微斗数、生肖和星座 |

## 8. 多用户与运营

### 8.1 Public Beta 用户隔离

- 服务器签发匿名 `HttpOnly` 会话 cookie。
- 每位访客的模型请求使用稳定、不可逆的安全标识。
- 个人数据保存在浏览器 `localStorage`。
- 服务器不提供跨用户读取接口。
- 管理员配置与个人分析分开。

### 8.2 全局管理

管理员可以：

- 切换维护模式。
- 开关 AI、微信导入、文化方法和完整示例。
- 修改公告、版本标签和隐私提示。
- 设置默认分析预设。
- 查看 AI 是否完成服务端配置。

管理员不能：

- 查看用户个人分析。
- 查看 API 密钥。
- 读取微信原文。
- 修改用户浏览器数据。

## 9. 安全与伦理

### 9.1 安全响应

检测到自伤、自杀、伤害他人或极端报复信号时：

1. 停止常规模拟。
2. 显示现实支持提示。
3. 建议联系身边可信任的人和当地紧急支持。
4. 允许用户整理一段可以发给现实支持者的话。

### 9.2 表述规则

- 禁止“你一定会”“命中注定”“准确率 90%”等绝对表述。
- 文化方法必须显示低参考度和文化限制。
- MBTI 必须使用“倾向”“阶段”“需要确认”。
- 群体统计不能转换为个人成功率。
- AI 输出必须显示实际提供商和模型名。

## 10. 非功能需求

### 10.1 性能

- 生产 Node 堆上限：768 MB。
- 容器内存上限：1 GB。
- 地图默认渲染节点不超过 40。
- 场景模型节点硬上限：200。
- 微信本地分析字符上限：600,000。
- API 请求体默认上限：1,000,000 字符。
- 地图交互期间不启动无限动画循环。
- 所有定时器、`ResizeObserver` 和事件监听器必须清理。

### 10.2 可访问性

- WCAG 2.2 AA 为目标。
- 所有核心按钮支持键盘。
- 颜色之外必须有文字状态。
- 当前尺度地图文字保持可读。
- `prefers-reduced-motion` 下关闭非必要动效。
- 表单字段使用明确标签和错误提示。

### 10.3 可靠性

- AI 超时：75 秒。
- AI 不可用时自动降级。
- API 返回 `Cache-Control: no-store`。
- 管理员登录每 15 分钟最多尝试 5 次。
- 生成、聊天和微信摘要使用独立限流桶。
- 健康检查地址：`/api/health`。

### 11.2 使用价值

## 12. 发布验收

Public Beta 发布前必须全部满足：

- `npm run check` 通过。
- `npm run build` 通过。
- `npm audit --omit=dev` 为 0 个已知生产漏洞。
- 新用户流程在桌面和移动视口走通。
- AI 正常和 AI 关闭两条路径都走通。
- 八字和紫微斗数启用、缺少字段、关闭三种状态都验证。
- 每条顶层和深层分支都能显示来源说明。
- 地图缩放、平移、双击焦点、拖动和重置通过。
- 管理员登录、保存、退出和错误密码通过。
- 维护模式阻断新生成请求。
- 本地数据刷新后恢复，清空后删除。
- 生产进程只有一个，端口固定。
- 进程 RSS 和容器内存低于预算。
