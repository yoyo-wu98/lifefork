## 1. 文档信息

| 项目 | 内容 |
| --- | --- |
| 文档版本 | 1.0 |
| 日期 | 2026-08-09 |
| 范围 | 用户端完整漏斗、AI 核心、方案地图、管理端、部署与性能 |

## 2. 执行结论

本轮以一个有真实职业选择、现金流约束、伴侣意见和早期用户反馈的测试用户完成全流程体验。系统已经具备完整可用链路：

```text
五问
  -> 可选微信摘要
  -> 可选补充材料
  -> 分析方法预设
  -> 服务器 AI 或本地降级
  -> 决策摘要与详细个人报告
  -> 可编辑时间线
  -> 多尺度方案地图
  -> 分支模拟对话
  -> 可复制、可导出的决策摘要
```

本轮解决的关键问题：

1. 详细报告缺少明确结论顺序，用户需要自己从长文中寻找下一步。
2. 分析方法首次展示七组开关和滑杆，理解成本过高。
3. 微信本地分析与服务器 AI 补充的完成状态不够明确。
4. 资产图把启发式相对值换算成精确金额，且换算倍率和比较图横轴存在错误。
5. AI 对话可能把模型自行提出的阈值写成已知事实。
6. 最终结果卡片使用通用建议，和前面已经完成的个性化分析脱节。
7. Webpack 文件监听器出现 `EMFILE` 与循环重启，可能造成高内存、CPU 抖动和电脑卡顿。

整改后，决策摘要成为报告和最终结果的共同数据源；高级方法、资产图按需展开；AI 来源和降级状态清楚可见；生产预览没有文件监听器。

## 3. 端到端体验审计

### 3.1 首页与进入体验

目标：用户在第一屏理解产品可以解决什么问题，并能在一分钟内开始。

当前结果：

- 首页使用直接文案说明“整理问题、比较方案、依据、成本和下一步”。
- 明确预计用时、无需账号、数据边界和非医疗建议。
- 主要入口清楚，演示体验保留为次要动作。

后续观察：

- 需要在真实微信内置浏览器、iOS Safari 和 Android Chrome 上补充可用性样本。
- 首页不增加复杂功能说明，避免推高开始成本。

### 3.2 五问访谈

目标：用最少输入覆盖当前选择、情绪、过去节点、隐藏动机和未来目标。

当前结果：

- 一次只显示一个问题。
- 提供可点击的灵感标签。
- 输入即时写入本地状态，返回和刷新可恢复。
- 中文输入按完整文本处理，聊天输入另有 IME 保护。

质量原则：

- 标签只提供表达帮助，不替用户定义答案。
- 问题内容直接进入 evidence，后续结论必须能追溯。

### 3.3 微信材料导入

目标：允许用户主动使用历史材料，提高主题、语气和关系模式的覆盖。

重构后的流程：

1. 用户粘贴文本或上传已导出的文本文件。
2. 浏览器先执行有界本地分析。
3. 页面展示主题、情绪和关键片段预览。
4. 用户可以直接采用本地结果，也可以主动触发服务器 AI 补充。
5. 服务器只接收本地摘要与脱敏标签。
6. 完成后明确显示模型、提供商、耗时或本地备用原因。
7. 离开页面后清除原文，只保留用户确认的摘要。

本轮交互修正：

- 去掉重复的“跳过”入口。
- 将不可用按钮改为“请先完成本地分析”，避免和分析按钮重名。
- 增加服务器 AI 完成状态和来源。
- 危机内容继续禁止发送模型。

### 3.4 分析方法

目标：普通用户快速继续，高级用户可以控制方法偏好和权重。

重构后的信息层级：

- 第一层只展示三个预设。
- 预设下方说明启用的方法数量。
- 单项开关和权重进入折叠的高级设置。
- 八字、紫微斗数启用后再显示出生信息和知情同意。
- 报告继续区分用户事实、统计参考、模型推断、性格倾向和文化解读。

### 3.5 个人报告与决策摘要

新增统一模块：

```text
src/lib/decisionBrief.ts
  -> buildDecisionBrief(SelfSkill, selectedFork?)
  -> DecisionBriefPanel
  -> ShareCard
```

决策摘要固定回答六个问题：

1. 用户现在要解决什么问题。
2. 当前核心冲突是什么。
3. 哪些材料形成了最强信号。
4. 哪个方案值得先验证。
5. 目前仍然缺少哪些信息。
6. 未来 14 天可以做什么。

详细报告继续保留方法贡献、参考度、证据、阶段性格、语气档案和限制。首次阅读顺序由“阅读完整报告”改为“先看摘要，再按需展开来源”。

### 3.6 时间线与人生地图

时间线承担事实校对，人生地图承担方案结构和多尺度探索。

当前边界：

- 时间线节点可以确认、修改、删除和新增。
- 地图保持过去在左、现在居中、未来在右。
- 父级时间段包含子级节点，同级大容器不重叠。
- 当前尺度文字可读，上级容器以低透明虚线保留上下文。
- 节点选中后展示收益、成本、状态变化、方法来源、假设和未知项。
- 高级结余图默认折叠，不参与推荐排序。

### 3.7 资产与结余示意

底层模型表示“相当于多少个月的当前可投资结余”，属于本地启发式比较。

本轮修正：

- 默认显示“个月结余”相对单位。
- 用户主动选择月结余档位后才执行金额换算。
- 去掉错误的额外乘 12，金额换算公式改为：`相对单位 × 每月可投资结余`。
- 比较图横轴按统一年份数量计算，曲线覆盖完整画布。
- 将“月度趋势”改为“下一年变化”，与实际计算一致。
- 明示未纳入起始资产、投资回报、税费和通胀。

这些图只用于观察方案间的相对差异，不能解释为资产预测。

### 3.8 分支对话与语气

AI 对话输入包含：

- Self Skill 摘要。
- 当前分支名称、时间尺度、收益和成本。
- 用户语气档案。
- 当前人生阶段语气。
- 最近校准反馈。
- 有界对话历史。

`dialogue.v6` 增加以下约束：

- 提取并单独提供用户真实标志性短语。
- 回复必须使用一个可用标志性短语，每次最多一个。
- 用户未提供的数字必须标为“建议阈值”或“待确认假设”。
- 行动计划必须符合用户要求的时间范围。
- 判断尽量区分已知材料、待确认假设和下一步。

### 3.9 最终结果

结果页已经从“人格标签 + MBTI + 随机建议”调整为可执行决策摘要：

- 当前问题。
- 选择查看的方案。
- 为什么值得验证。
- 需要先确认什么。
- 未来 14 天行动。
- 分析来源和参与整理的材料数量。

输出支持 PNG、文字版和完整 JSON。图片和文字版不包含微信原文。

## 4. 模块边界与耦合关系

| 模块 | 输入 | 输出 | 允许依赖 | 禁止承担 |
| --- | --- | --- | --- | --- |
| Input Flow | 五问、可选材料 | `GenerateSelfSkillInput` | Store、safety | 模型调用细节 |
| WeChat Ingestion | 用户主动导入文本 | `WeChatAnalysis` | 本地解析、脱敏、可选 API | 自动抓取微信数据库 |
| Analysis Settings | 方法预设和权重 | `AnalysisSettings` | method registry | 直接生成结论 |
| Self Model | 输入、evidence、AI 补充 | `SelfSkill` | analysis、voice、fork rules | 页面展示状态 |
| Decision Brief | `SelfSkill`、可选分支 | `DecisionBrief` | 纯函数 | 网络、存储、UI 状态 |
| Timeline | `TimelineNode[]` | 用户校对后的节点 | Store actions | 推断用户未来 |
| Life Map | `ForkPath[]` | 节点预览和选择 | layout、camera、visibility | AI 网关调用 |
| Dialogue | Skill、分支、消息 | `ChatMessage` | AI route、本地 fallback、safety | 修改人生地图拓扑 |
| Share | `DecisionBrief`、Skill | PNG、文本、JSON | export utilities | 新增独立结论 |
| Admin | `RuntimeConfig`、编辑配置 | 全局开关和文案 | server config store | 读取用户个人材料 |

最关键的耦合规则：

```text
SelfSkillPanel ─┐
                ├─> buildDecisionBrief() <─ SelfSkill / selected ForkPath
ShareCard ──────┘
```

报告与分享结果不能各自生成不同结论。`DecisionBrief` 保持纯函数，方便单元测试、服务端复用和未来版本迁移。

## 5. 多用户与管理端

公开测试采用匿名浏览器会话：

- 每个浏览器获得不同的签名会话 Cookie。
- 个人分析保存在各自 localStorage。
- AI 密钥只在服务器环境变量中。
- 管理端使用独立的 HttpOnly 会话。
- `/api/admin/config` 未登录返回 401。
- 管理操作要求同源请求并有登录限流。

管理端当前可控制：

- 服务开放或维护状态。
- AI、微信导入、文化方法和演示入口。
- 首页与导航文案。
- 全局公告、隐私提示和免责声明。
- 默认分析预设。

结果页使用用户材料动态生成，后台不再配置随机通用建议。

## 6. 性能与稳定性

### 6.1 已定位的问题

Webpack dev 文件监听器曾持续输出：

```text
EMFILE: too many open files, watch
Found a change in next.config.ts. Restarting the server
```

循环重启会重复创建编译器、监听器和缓存，导致 CPU、内存和响应时间持续恶化。

### 6.2 修复

- 默认开发命令切换到 Turbopack。
- Webpack 只保留为 `npm run dev:webpack` 兼容入口。
- 正式验收使用 `npm run build` 和 `npm run start:3005`。
- 同一时间只允许一个 3005 进程。
- Next 构建工作线程限制为 2。

生产模式实测监听进程打开 21 个文件句柄，没有文件监听错误和重启风暴。

## 8. 发布门槛

每次发布必须执行：

```bash
npm run check
npm run build
npm run qa:product
npm run qa:ai:providers
npm audit --omit=dev
```

修改 Prompt、schema、AI 网关或安全规则时增加：

```bash
npm run qa:ai -- --require-live-ai
```

发布条件：

- 关键失败为 0。
- 生产服务器没有监听器重启。
- 危机输入不进入模型。
- 用户材料外的数字明确标注为建议或假设。
- 分享结果与报告使用同一决策摘要。
- 管理端和用户端数据边界保持隔离。

## 10. 最终判断

LifeFork 当前已经形成一条连贯的可用产品路径。核心竞争力来自四个组合：用户证据、阶段语气、多方案模拟、可执行决策摘要。AI 是否成功调用只是基础条件；长期指标应持续衡量相关性、可核对性、行动完成率、语气认可率和用户修正后的改善。

本轮可进入受控公开测试。扩大访问量之前，仍需完成真机回归、监控告警、全局成本护栏和真实用户盲评。
