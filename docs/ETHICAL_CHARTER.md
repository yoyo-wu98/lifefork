# LifeFork Ethical Charter

> Owner: Product & Research Team
> Last updated: 2026-04-29
> Scope: LifeFork 的伦理边界、文案红线、数据原则、安全升级和跨团队验收标准。

## 1. Charter Statement

LifeFork 是面向活人的自我模拟工具。它帮助用户整理材料、看见模式、探索分支和校准表达，但不预测命运、不诊断心理状态、不替用户做决定，也不鼓励用户依赖 AI 陪伴。

产品的伦理底线：

> 用户拥有自己的材料和解释权。LifeFork 只能提供可编辑、可反驳、可删除的可能性模拟。

## 2. Non-Negotiable Principles

### 2.1 User Agency First

- 用户始终是最终解释者和决策者。
- 系统不得使用强制、羞辱、恐吓或道德裁判式表达。
- 对重大选择只能展示路径、代价、假设和小行动，不给最终命令。

### 2.2 Simulation, Not Prediction

- 所有未来表达必须保持概率性和假设性。
- 分支节点代表“可能路径”，不是预言结果。
- 分享卡片和传播文案不得把 LifeFork 包装成算命、宿命或未来判决。

### 2.3 Reflection, Not Therapy

- LifeFork 不提供心理诊断、治疗方案或医疗建议。
- 当用户表达自伤、伤害他人、严重绝望或现实危机时，系统应停止常规模拟，转向现实支持建议。
- 产品文案不得使用“治愈”“诊断”“疗效保证”等承诺。

### 2.4 Privacy by Default

- V0 原型默认本地存储和本地规则分析。
- 用户导入的微信、日记、聊天记录等材料必须有明确用途说明。
- 完整原文默认不写入 `Self Skill` 的长期字段，除非用户明确选择。
- 任何未来模型 API 外发都必须先给出清楚提示，并尽量最小化外发内容。

### 2.5 Editable and Deletable Memory

- 用户可以查看、导出和清空本地数据。
- 用户可以修正时间线、语气、节点和画像。
- 系统不得把生成判断伪装成不可反驳事实。

## 3. Product Red Lines

禁止：

- “你一定会走向……”
- “这是你的命运”
- “这是你的真实人格”
- “你应该马上做某个重大决定”
- “我比任何人都懂你”
- “只有我会一直陪你”
- “这能治好你的焦虑/抑郁/创伤”
- 默认上传用户聊天记录、日记或通讯录。
- 在用户没有充分理解用途前要求粘贴高敏材料。

需要强提示：

- 用户导入私人聊天记录。
- 用户开启真实 AI API 或云端同步。
- 用户导出、分享、删除数据。
- 用户在对话中表达危机或伤害风险。

## 4. Sensitive Scenario Handling

| Scenario | Product stance | Required response |
| --- | --- | --- |
| 自伤或伤害他人 | 停止模拟 | 建议联系现实可信任对象、当地紧急服务或专业支持 |
| 医疗/心理诊断 | 不诊断 | 说明产品限制，建议寻求专业人士 |
| 分手/离职/搬家等重大决定 | 不替用户决定 | 展示路径、代价、可逆小实验 |
| 用户要求预测未来 | 拒绝确定预测 | 转向时间尺度、变量和可能性 |
| 用户表达强依赖 AI | 降低陪伴承诺 | 鼓励现实关系和自主判断 |
| 用户导入敏感材料 | 最小化处理 | 清楚说明保存位置、用途、删除方式 |

## 5. Copy Standards

推荐语气：

- 克制。
- 具体。
- 可反驳。
- 有证据意识。
- 给用户保留决定权。

示例：

- “在这条路径上，可能出现的代价是……”
- “这更像一个假设，不是结论。”
- “如果把尺度缩小到一周，可以先验证……”
- “这条判断来自你提到的……如果不准确，应该允许你改掉。”

不推荐语气：

- 神秘化。
- 绝对化。
- 过度亲密。
- 诊断式。
- 指令式。

## 6. Data Handling Rules

V0:

- 数据保存在浏览器 `localStorage`。
- 无账号、无数据库、无真实模型 API 依赖。
- 微信聊天记录只做本地规则分析。
- 清空入口必须可用。

MVP and later:

- 若引入真实 AI API，必须显示 AI enabled/disabled 状态。
- 外发内容应优先使用摘要、证据片段和脱敏字段。
- 用户必须能删除云端数据。
- 分享内容必须使用白名单字段，默认隐藏原文。

## 7. Cross-Team Review Checklist

Product & Research:

- 用户价值是否清楚。
- 是否存在过度命运化、治疗化、陪伴化。
- 是否有研究问题和可用性测试任务。

AI Team:

- prompt 是否要求证据、概率表达和边界声明。
- fallback 是否保持同样的安全边界。
- 危机场景是否停止常规模拟。

UI Team:

- 隐私和删除入口是否可见。
- 地图是否让用户理解“可能路径”而不是“注定结果”。
- 安全提示是否足够显著。

QA Team:

- 是否覆盖本地/AI 两种模式。
- 是否覆盖危机关键词。
- 是否验证导出、分享、清空。
- 是否检查禁用表达没有出现在核心路径。

## 8. Release Gate

任何公开发布前，必须满足：

- README、需求文档、产品内文案的非目标一致。
- 用户可完成导出和清空。
- 危机关键词触发通过。
- 至少 3 名试用者能正确描述 LifeFork 不是命运预测或心理治疗。
- Product & Research 完成一次反模式清单复核。
